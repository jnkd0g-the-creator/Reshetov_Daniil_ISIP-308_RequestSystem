# 1. Цель и конфигурация

Цель — упаковать систему и проверить воспроизводимый запуск вне исходного venv. Ветка feature/lab8 содержит Dockerfile, docker-compose.yml, .dockerignore и .env.example. Изменяемые настройки читаются из переменных окружения: режим, путь SQLite, порт и Secure-cookie. Compose читает .env, Python — только переменные ОС. Настоящие пароли и локальные базы исключены из Git и build context.

Исходный Dockerfile перед ревью сохранён в docs/deployment/Dockerfile.before. После ревью добавлены non-root USER 10001, доступный ему каталог данных и Docker healthcheck, проверяющий не только процесс, но и БД. Слои установки requirements перед COPY src сохраняют кэш. Подробная таблица «до → после» — docker_review.md.

# 2. Фактическая сборка и запуск

Docker Engine 29.9.3 действительно собрал образ Python 3.10. Контейнер инициализировал 12 учебных заявок, запущен на 127.0.0.1:8001, стал healthy. Проверены вход, GET списка и POST 201. Затем контейнер пересоздан: ID изменился, заявка и сессия сохранились в именованном томе. Команды выполнены скриптом scripts/docker_evidence.py; полный вывод — docs/deployment/docker_run.txt.

# 3. Удалённый деплой: не выполнен

BLOCKED: заказчик не предоставил согласованный SSH-хост/учебный сервер или внешний адрес. Локальный Docker на своей машине не выдаётся за проверенную удалённую среду. Поэтому ЛР8 нельзя считать полностью закрытой по методичке. Никакие внешние облачные ресурсы, публичные порты или платные услуги без согласования не создавались.

docs/deployment/README.md содержит инструкцию с нуля: clone, env, build, init, up, TLS reverse proxy, проверка health/UI/API, сохранность, обновление и резервирование. deployment_status.json явно содержит remote_url=null и BLOCKED. После согласования сервера требуются реальный запуск и внешние скриншоты.
