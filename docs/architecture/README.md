# Архитектура CoffeeDesk (ЛР3)

## Рассмотренные варианты

| Критерий | Слоистый модульный монолит | Микросервисы заявок/пользователей |
|---|---|---|
| Простота | Один Python-процесс и SQLite | Отдельные процессы и протоколы |
| Тестируемость | Сервис + временная SQLite, TestClient | Контрактные/сетевые тесты нескольких сервисов |
| Расширяемость | Новые модули внутри процесса | Независимые релизы, но сложная согласованность |
| Внедрение | Один контейнер и сохраняемый том | Оркестрация, сеть, несколько хранилищ |
| Учебный проект | Соразмерен 4 ролям и небольшому объёму | Избыточные инфраструктурные затраты |

Выбран **слоистый модульный монолит**. За: повторное использование сервисов
в HTTP/UI, транзакции одной БД, воспроизводимый запуск. Против: SQLite имеет
одного писателя, масштабирование и независимые релизы ограничены. Несколько
worker-процессов не используются; при росте — PostgreSQL и миграции.
Оценка качественная, измерений затрат микросервисного варианта не было.

## Слои и запреты

| Слой | Ответственность | Запрет |
|---|---|---|
| Presentation/controller | HTTP, JSON, Pydantic, cookie, передача в сервис, показ ошибок | Нет SQL и решений о переходах статуса |
| Service | Права доступа, состояние, назначение, аудит, координация транзакции | Нет HTML, FastAPI Response и сырого SQL |
| Repository/data access | Параметризованный SQL, отображение строк, транзакция | Не решает, какая роль закрывает заявку |
| Database | FK, CHECK, UNIQUE, NOT NULL, индексы, сохранность | Нет UI и ролевого workflow |

UI вызывает API, API вызывает тот же сервис. Проверки авторизации объектов
находятся в сервисе, а не только в скрытии кнопок. Бизнес-операция и история
выполняются в одной транзакции (`BEGIN IMMEDIATE` для записи). Чтение не берёт
write-lock. Подключение открывается на сценарий, FK и timeout задаются каждый раз.

## Компоненты и модули

| Компонент | Вход | Результат |
|---|---|---|
| `RequestService` | текущий User, validated DTO, id/фильтры | заявка/список/комментарий либо DomainError; проверяет роли/статусы |
| `AuthService` | логин/пароль либо session token + csrf | публичный User, новая сессия; logout удаляет её |
| `Repository` | connection, параметры поиска/записи | dict-строки и идентификаторы; не включает пароль в публичный User |
| `Database` | путь SQLite, режим read/write | соединение/unit of work с commit/rollback и FK |
| `create_app` / routes | Settings, HTTP request | FastAPI app, JSON/файлы интерфейса, унифицированные HTTP-ошибки |

Предметные модули: users/roles, requests, statuses, categories, cafes,
comments/history, sessions. Для малого проекта они сгруппированы в небольшое
число файлов, а не в пустые пакеты по каждой таблице.

## Структура

```text
src/coffeedesk/
  __init__.py, __main__.py   # версия и CLI инициализации/запуска
  config.py                 # env и Settings
  database.py               # создание connection, транзакция, schema/seed
  models.py                 # DTO и public response schemas
  repository.py             # доступ к данным
  services.py               # бизнес-сценарии и AuthService
  security.py               # PBKDF2 и хеширование токенов
  api.py                    # HTTP controller/router
  app.py                    # composition root и обработчики ошибок
  static/                   # HTML, CSS, JS
docs/database/              # схема, seed, queries, учебный снимок
tests/                      # smoke-тесты этапов разработки
testing/lab9/               # план/кейсы/доказательства
testing/lab10/              # изолированные автотесты и регрессия
```

Схема и seed включаются в Docker-образ явно, а не скачиваются из сети.

## Архитектурное ревью (тот же агент, не независимое)

| Замечание | Решение | Причина |
|---|---|---|
| Права только в UI обходятся HTTP-запросом | Исправлено проектом | Проверять объекты в RequestService |
| История отдельным commit может потеряться | Принято | Одна транзакция на бизнес-сценарий |
| Repository содержит `if role == admin` | Отклонено такое смешение | Допустимый scope рассчитывает сервис |
| БД как глобальное connection неудобна для тестов/потоков | Принято | Соединение на unit of work, DB path внедряется |
| Перейти сразу на микросервисы | Отклонено | Нет распределённой нагрузки, сложнее сдача |
