# План тестирования CoffeeDesk · ЛР9

Дата: 12.11.2026. Исходная версия: 1.0.0, commit `9e9cb12` (после ЛР8).
Версия конкретного прогона и динамический адрес: `environment.json`.
ОС Ubuntu 26.04, Python 3.10.11 (проектное .venv), Chromium 140,
Playwright 1.55.0, curl, SQLite 3.46.1. Локальный UI: http://127.0.0.1:8000,
контейнер: http://127.0.0.1:8001. **Набор ЛР9 запускается отдельно** на временном
локальном порте с собственной БД, не меняет эти две базы.

## Объект и область

Проверяются FR-01–16 и AC-01–10: создание, список/карточка, редактирование,
русскоязычный поиск, фильтры, роли/скрытие чужих объектов, назначение,
последовательные статусы, комментарий, подтверждение архива, ошибки, сохранение
UI/API → SQLite и OpenAPI. Тестовые записи и пользователи вымышлены.

Не входят: реальный ремонт, платежи/SMS/вложения (вне ТЗ), нагрузка нескольких
писателей, промышленный пентест, реальные персональные данные. Удалённая сеть,
DNS/TLS и ручной прогон лично студентом пока BLOCKED из-за внешних условий.

## Виды и критерии

- Позитивные функциональные: ≥5 (создание, список, поиск, изменение, статус).
- Негативные: ≥4 (обязательное поле, тип ID, статус, отсутствующая запись).
- Границы: ≥3 (3/120 символов темы, 4000 описания, пустой поиск, спецсимволы).
- Роли: ≥2 (свои/чужие, запрещённое создание мастером, CSRF, без входа).
- Интеграция UI/SQLite: ≥2 (создание/аудит, изменение статуса/история).
- API: ≥4 (GET/POST/PATCH/DELETE + ошибки и HTTP-коды).

Начало: поднята исходная версия, схема/seed применены, 12 заявок, 6 пользователей,
5 категорий, доступны четыре роли, отдельная БД и браузер, ТЗ/API согласованы.
Завершение инструментального этапа: ≥20 кейсов реально выполнены; у каждого
статус и доказательство, каждый дефект сначала записан, затем исправлен и
повторно проверен; нет необъяснённых FAIL. BLOCKED не включается в процент успеха.
Полная сдача отдельно требует ручной приёмки студентом и внешнего деплоя.

## Способ и честность результатов

`python scripts/run_lab9.py` воспроизводит пользовательские действия браузером,
проверяет реальные HTTP и SQL. Поля `execution_mode` и `manual_status` в CSV
не позволяют выдать автоматизацию за самостоятельный ручной прогон студента.
Это честные инструментальные результаты агента: они не заменяют пункт
«пройти вручную» методички. Для самостоятельного повторения все шаги и данные
содержатся в CSV; студент обновляет отдельный `manual_review.md` после выполнения.

Планирование/ревью ИИ: `docs/ai_log.md`, ЛР9; модель GPT-6.1 Sol.
Секреты не входят в evidence; логинные ответы и заголовки сессий не сохраняются.
Ожидания задаются до запуска; при FAIL результат не меняется на PASS без retest.
Исходное доказательство сохраняется даже после исправления.
