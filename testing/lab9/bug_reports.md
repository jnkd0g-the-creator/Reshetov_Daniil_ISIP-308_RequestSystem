# Реестр дефектов CoffeeDesk

## BUG-01 — boolean принимается за идентификатор кофе-бара

- **Среда/версия:** Ubuntu 26.04, Python 3.10.11, FastAPI TestClient,
  отдельная SQLite; commit `a4ed69d04dccd82fcc4162b7d0e3f81cac409e70`.
- **Дата:** 12.11.2026.
- **Важность:** Medium. Нарушает JSON-контракт integer ID: неправильный тип
  создаёт заявку с неявно выбранным баром 1 вместо отказа; не даёт обхода ролей.
- **Предусловия:** schema/seed, вошедший admin, новая временная БД (12 заявок).
- **Шаги:** 1) Войти. 2) POST /requests с валидной темой/описанием,
  `cafe_id=true`, `category_id=1`, cookie и CSRF. 3) Проверить код и число строк.
- **Ожидается:** 422, число заявок 12, boolean не является целым ID JSON.
- **Фактически:** 201, cafe_id=1, число строк 13. Pydantic по умолчанию
  преобразует True в int(1).
- **Доказательство:** `evidence/BUG-01_before_fix.json/txt`, воспроизведение
  `python scripts/reproduce_bool_id.py`. Скрипт действительно завершился
  AssertionError: Expected strict integer validation (422), got 201.
- **Статус на момент регистрации:** Новый. Исправление ещё не внесено;
  исходное доказательство FAIL сохраняется отдельно и не заменяется PASS.

### Исправление и повторная проверка

`PositiveId` в models.py изменён на `Field(gt=0, strict=True)` для JSON-тел
создания, изменения и назначения. Path/query остаются отдельными валидаторами
HTTP-параметров, поэтому строковое представление ID в URL не ломается.
Добавлен регрессионный тест `tests/test_validation_regression.py`.
Повтор исходного сценария: **422, число строк 12, PASS**;
`evidence/BUG-01_retest.json/txt`. Исходный FAIL не перезаписан.
Полный существовавший набор: **3 passed**. Статус: **повторно проверен**.
В retest фиксируются commit, SHA256 models.py и наличие незакоммиченных исходников.

Самостоятельный ручной прогон студентом ещё не выполнен. Реестр содержит
инструментально подтверждённый дефект, а не придуманный пример ради задания.

## TEST-01 — гонка ожидания в браузерном тесте TC-02 (не дефект продукта)

- **Версия:** приложение a49f4f5, первый scripts/run_lab9.py.
- **Шаги:** открыть список → нажать ссылку заявки → немедленно проверить
  `.badge.new`, не дожидаясь заголовка карточки.
- **Ожидается:** тест дождётся карточки и проверит её единственный статус.
- **Фактически:** Playwright strict mode находит 6 статусов ещё в списке;
  первый прогон 29 PASS / 1 FAIL. Переход приложения работает, селектор теста
  проверяет старый DOM до завершения асинхронного render.
- **Важность:** Low (тестовая инфраструктура), не ошибка бизнес-продукта.
- **Доказательство:** `initial_failure/TC-02.json/png`, результаты и версия рядом;
  полный исходный прогон сохранён Git-коммитом до исправления теста.
- **Статус при регистрации:** Новый. Исправлять нужно ожидание заголовка
  карточки, а не ослаблять проверку `.first()` и не менять приложение.

В итоговых метриках продуктовых дефектов TEST-01 учитывается отдельно от BUG-01.

### Retest TEST-01

Добавлено ожидание заголовка конкретной карточки после клика, затем выполняется
исходный строгий assert статуса. `.first()` не использовался для сокрытия
множественного результата. Приложение не менялось. Повторно запущены **все
30 кейсов и 29 curl-запросов: 30 PASS, 0 FAIL; curl 29 PASS**.
Статус TEST-01: **повторно проверен**. Первоначальные 29/1 и ошибка не скрыты,
они сохранены в initial_failure/ и Git-истории.
